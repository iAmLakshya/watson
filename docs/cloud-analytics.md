# Organization analytics and account email actions

Watson reports organization and member adoption, team comparisons, assistant use, saved coaching assessments, and technical activity. Reports support date/team/user filters and exports. Named counters and missing-data labels make each measurement's scope explicit.

Open Analytics → Organization & teams, or the organization analytics section in Sync & sharing. Choose an organization, UTC date range, permitted team and member, and refresh. Reports also offer seven-, thirty- and ninety-day presets, labeled demo inclusion, per-member/team tables, feature and mode breakdowns, source explanations, and paired daily meeting/event bars. Select a member, team or day to drill down. CSV export uses the applied filters and the native save dialog. An optional thirty-second refresh reads the current report while the page is visible; it does not upload local workspace data.

The backend enforces current permissions for both JSON and CSV. Organization admins can report across the organization. Team managers can report only across managed teams and their current members. Other members see their own activity. Removing membership changes eligibility immediately. Sessions are attributed through an explicit organization ID or an actual shared mode belonging to that organization; another organization’s explicit ID takes precedence. Unscoped private sessions are excluded. Overall totals deduplicate each session and event, while team breakdowns can overlap for members of multiple teams.

Uploaded session telemetry and independently recorded server events remain separate. Reports show sessions, capture durations, saved answers and their completed/error counts, provider request/token measurements, screenshots, knowledge/web references, response latency and saved coaching scores. Means without samples and incomplete legacy metrics appear as an em dash. Known empty sums are zero. Technical “last server activity” is the latest authenticated request; app-open time, app version and a complete calendar coverage denominator remain unavailable when not recorded. Reports do not return notes, transcript text, questions, answer bodies, coaching feedback, private prompt content or credentials. Spreadsheet formula prefixes in exported labels are neutralized.

The renderer discards a previous report and export state when the account, server, organization role or authorization revision changes. A response must still match the request’s account, server, role, authorization revision and filters before it can render. Refreshing account permissions or receiving a scope-denied response invalidates prior views. Exports are disabled for unapplied filters. Source and missing-measurement explanations stay attached to the report.

Cloud account settings preserve `emailVerified` and `emailVerifiedAt`. The client reads public email capabilities and disables verification/recovery actions when operator delivery is absent. Requesting verification or password recovery returns an accepted message, not a delivery claim or raw token. Known and unknown reset addresses receive the same response. Confirmation and reset happen through explicit browser forms from the email link; opening the link does not consume it. A successful reset revokes existing device sessions, and the desktop clears revoked sign-in state on its next authenticated request. Email changes clear verification. Authentication, recovery and verification tokens never enter renderer status or synced workspace records.

`tests/cloud-analytics-client.test.ts` uses real HTTP and SQLite to verify role scopes, explicit/shared-mode attribution, UTC filters, overlapping-team deduplication, matching CSV filters, formula safety, null legacy measurements and removal. `scripts/check-cloud-analytics-ui.mjs` renders the actual React component in installed headless Chrome with deferred IPC fixtures to verify stale responses and revoked views; this fixture does not establish native IPC or packaged GUI behavior. `tests/cloud-auth-client.test.ts` verifies configured and disabled capabilities, verification, browser confirmation, uniform recovery requests and session revocation against a local email API fixture. No live provider credentials or customer deliveries are used. Native save-dialog and packaged GUI checks remain part of the release gate.

Version0.4 adds separate standardized first-text/completion means and measured sample counts. Both originate at application request acceptance and include context preparation; they exclude screen paint and speech-input delay. Legacy values are not substituted into these means. The existing `averageLatencyMs` export field is retained as a deprecated legacy average whose historic definition may differ by client. Missing or older-server measurements display an em dash. Refused, partial/error and empty answers do not contribute to standardized response means.
