Watson now has server connectors for Google Calendar, Merge CRM and ATS, and approved public knowledge links. They use actual provider protocols and persist account state, imports, cursors, and writeback jobs in SQLite. Local HTTP provider fixtures verify those protocols. Live accounts remain a separate verification gate because no Google or Merge credentials were supplied.

Set `WATSON_CONNECTOR_ENCRYPTION_KEY` to a persistent, randomly generated 32-byte base64 key on the server. Google also needs `WATSON_GOOGLE_CLIENT_ID`, an optional `WATSON_GOOGLE_CLIENT_SECRET` for a confidential client, and `WATSON_GOOGLE_REDIRECT_URI` when the externally reachable callback differs from the server origin. Register `/api/v1/connectors/google/callback` as the redirect. Merge needs `WATSON_MERGE_API_KEY`; `WATSON_MERGE_REGION` accepts `eu` or `apac`, otherwise the US API is used. These credentials belong in operator environment or a secret manager. AI provider keys remain in the desktop's secure storage.

Google connection begins with an authenticated `POST /connectors/google/start`, then the desktop opens the returned `authorizationUrl` in the browser. A cryptographically random, ten-minute state is tied to the Watson user; its PKCE verifier is encrypted. The callback consumes that state before exchanging the code, checks the granted Calendar read scope, and encrypts access and refresh tokens. Browser requests receive a readable connection page; API clients retain JSON. An expired or replayed state fails. Refresh preserves an existing refresh token when Google omits a replacement. Invalid refresh authorization produces a reconnect state. [Google OAuth guidance](https://developers.google.com/identity/protocols/oauth2/resources/best-practices)

`GET /connectors/{id}/calendars` loads all calendar list pages, preserves prior selection, and selects the primary calendar on the first load. `PUT` to the same path saves `{calendarIds:[...]}` and removes events from calendars that were deselected. `POST /connectors/{id}/sync` imports all selected calendars, follows event page tokens, and commits each calendar only after its last page. Incremental sync uses Google's final `nextSyncToken`; cancellations remove local events. A `410` clears the expired calendar cache and cursor before a full synchronization. Imported events match Watson's shared `CalendarEvent` structure, including attendee names and emails, join URL, and source provenance. [Calendar lists](https://developers.google.com/workspace/calendar/api/v3/reference/calendarList/list), [incremental sync](https://developers.google.com/workspace/calendar/api/guides/sync)

Google disconnect attempts provider token revocation, then removes credentials, pending states, selected calendars, imported events, and cursors locally even if the provider is unavailable. All connector tables have foreign keys that cascade when an account, organization, or team is deleted. Imported document cleanup checks its connection provenance and scrubs historical personal sync data as well as current content.

Merge connectors require an authenticated organization admin. A team connector also verifies that its team belongs to that organization. Reads require current organization membership and, where applicable, team membership; organization admins can read across teams. Configuration, sync, and writeback require an admin. `orgId`, `teamId`, and contact IDs from a payload confer no permission.

`POST /connectors/merge/link` accepts `{category:"crm"|"ats",orgId,teamId?}` and creates a real Merge Link token and hosted link. Its exchange state belongs to the initiating admin and expires after 30 minutes. `POST /connectors/merge/exchange` accepts that `state` and the `publicToken` returned by Merge Link. A dashboard account token can instead be supplied to the authenticated `/connectors/merge/connect` route; it is verified against `account-details` before encrypted storage. [Merge Link](https://docs.merge.dev/merge-unified/crm/linked-account/link-token/create), [account token exchange](https://docs.merge.dev/merge-unified/crm/linked-account/account-token/retrieve)

CRM imports contacts, notes, engagements, tasks, and users; ATS imports candidates, activities, and users. Imports follow the provider's `next` cursor, reject loops or paths outside the configured official API, use `modified_after` watermarks, and process reported deletions. Email matching returns the person and prior associated activity. `/connectors/context` and the cloud `/context` provider expose only facts permitted by current membership. Original record URLs are retained when the provider supplies them. Merge facts remain separate from revisioned cloud resources. [Merge authentication](https://docs.merge.dev/merge-unified/hris/merge-api-basics/authentication), [contact paging](https://docs.merge.dev/merge-unified/crm/common-models/contacts/list), [ATS candidate fields](https://docs.merge.dev/merge-unified/ats/common-models/candidates/the-candidate-object)

Writeback is explicit. `POST /connectors/{id}/writeback/preview` takes `meetingId`, `targetId`, optional edited `notes`, and `includeActions`, validates access to the meeting and imported destination, and returns the exact local content plus `previewToken` and `previewExpiresAt`. The opaque token references an encrypted ten-minute snapshot bound to the author, connection, destination, title, notes, actions, and ATS remote user. Enqueue requires that `previewToken`, `confirmWriteback:true`, and a stable `idempotencyKey`. It rechecks the current preview under the same SQLite write lock used to consume approval and create jobs. A concurrent content or destination change returns `preview_changed` and queues nothing. A token cannot authorize a different author or a second job key; an identical idempotent replay returns the existing group. CRM writes a Note and, when requested, separate Task jobs for actions. ATS writes a private NOTE Activity and requires the provider's `remoteUserId`; selected actions are appended to its body. Queued payloads are encrypted. The worker rechecks the original requester's admin permission immediately before sending. [CRM notes](https://docs.merge.dev/merge-unified/crm/common-models/notes/create), [CRM tasks](https://docs.merge.dev/merge-unified/crm/common-models/tasks/create), [ATS note activities](https://docs.merge.dev/merge-unified/ats/common-models/activities/create)

Rate-limited write jobs retry with provider `Retry-After` and bounded backoff. A lost network response, server error, or interrupted running job becomes `uncertain` because the provider might have committed the write. Retrying it requires `confirmPossibleDuplicate:true`; successful jobs cannot be resent. Provider errors and returned credential values are not written into user-facing error text. `/jobs` shows persisted status, attempts, remote ID, and classified error; `/jobs/run` runs due jobs; `/jobs/{jobId}/retry` retries a permitted failed job.

`PATCH /connectors/{id}/settings` accepts a synchronization interval from 5 to 10,080 minutes and `autoSync`. Polling is disabled initially. The server worker checks enabled connections every 30 seconds and also executes previously authorized writeback jobs. It drains a live tick during shutdown. Merge settings additionally accept local name/email/text field paths and ATS `remoteUserId`. Provider `/health`, `/field-mappings`, `/remote-fields`, and `/target-fields` expose actual synchronization status and field metadata. Remote mapping creation, patch, and deletion require `confirmMappingChange:true` and reset local import watermarks. Merge makes those changes effective at its next provider sync and restricts programmatic field mapping to its Enterprise plan. [Merge field mappings](https://docs.merge.dev/merge-unified/crm/linked-account/field-mapping)

`POST /connectors/urls` accepts an explicit `approveUrl:true`, URL, title, optional organization/team scope, interval, and `autoSync`. It supports public HTML, plain text, Markdown, CSV, and JSON lists. Sync retains original source URLs, follows same-origin JSON `next` or HTML next-link pagination, strips script/style content from HTML, replaces changed pages, and removes vanished pages. URLs use HTTPS port 443 in production. DNS resolution rejects local, private, reserved, and IPv4-mapped IPv6 destinations; the validated address is pinned in the actual socket lookup. Redirects cannot leave the approved origin. Credentials in URL authority are rejected. Response sizes, redirects, and page counts are bounded. A loopback fixture exception exists only as a programmatic test option, never through server environment or HTTP configuration.

The connector HTTP contract is in [openapi.json](../server/src/connectors/openapi.json). [connectors.test.ts](../server/tests/connectors.test.ts) verifies OAuth PKCE/state, refresh, calendar pagination/selection/cancellation/410, credential deletion, configuration errors, CRM/ATS imports and ACLs, matching, approved writeback, idempotency, rate retry, uncertain response/restart recovery, revoked permissions, remote mappings, URL pagination/cleanup/SSRF rejection, and opt-in scheduling. connectors-validation.json (`evidence/connectors-validation.json`, local diagnostic) records the executed evidence. Fixtures prove implementation and protocol behavior; they do not prove access to a customer's Google or Merge account or availability of every vendor-specific field.
